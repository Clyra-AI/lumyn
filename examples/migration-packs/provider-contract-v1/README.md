# Provider Change Contract v1 example

This source-safe example demonstrates the M3 normalization boundary. The
source and target OpenAPI descriptions are inert, pinned inputs. The
declaration records the reviewed relationship between their operations and
cites both exact evidence identities. Lumyn may derive stable-operation
signature changes directly; a rename or removal stays ambiguous until a
reviewed mapping such as this one exists.

These fixtures do not represent provider confirmation, provider-channel
delivery, consumer installation, repository authority, or a real customer.
Runtime tests generate and validate the public-derived contract, independent
provider confirmation, signed publish kit, pinned-channel intake, and attended
recovery result without committing a signing key.
